## Описание проблемы

После отключения VPN-клиента (AmneziaVPN, Nekoray, v2rayN, WireGuard, OpenVPN и аналогичных) интернет на хосте перестаёт работать: браузер не открывает страницы, `ping` до публичных адресов не проходит, DNS-запросы не резолвятся. При этом сам сетевой адаптер «жив» — Wi-Fi/Ethernet подключение активно, физически связь с роутером есть.

Проблема возникает из-за того, что VPN-клиент при подключении модифицирует таблицу маршрутизации системы и подменяет DNS-резолверы, но при аварийном или некорректном завершении работы не возвращает их в исходное состояние. Виртуальный tun/tap-адаптер исчезает, а маршруты, указывающие на него, остаются «висеть» и ломают доставку пакетов.

## Причины

1. **«Осиротевшие» маршруты.** В таблице маршрутизации остаются записи, которые указывают на уже несуществующий tun-интерфейс VPN. Любой пакет, попадающий под такой маршрут, уходит «в никуда».
2. **Испорченный DNS-кэш.** VPN часто подставляет собственные DNS (например, `1.1.1.1`, `10.x.x.x` внутри туннеля). После отключения эти записи остаются в кэше резолвера и в настройках интерфейса.
3. **Некорректное завершение клиента.** Основные триггеры:
   - закрытие окна клиента крестиком вместо кнопки «Disconnect»;
   - принудительное завершение процесса через Диспетчер задач / `kill`;
   - уход компьютера в спящий режим / закрытие крышки ноутбука при активном VPN;
   - вылет клиента по ошибке.
4. **Залипший MTU / настройки интерфейса.** Некоторые клиенты меняют MTU физического адаптера и не возвращают его к значению по умолчанию.

## Как избежать проблемы без скриптов

- Всегда отключайте VPN **внутри интерфейса клиента** кнопкой «Disconnect» / «Выключить».
- Дайте клиенту 2–3 секунды на корректное удаление tun-интерфейса, прежде чем закрывать приложение или крышку ноутбука.
- Не отправляйте ПК в сон с активным VPN — сначала отключите туннель.
- Если клиент поддерживает опцию «kill switch», проверьте, что она не блокирует трафик после разрыва (иначе будет казаться, что интернет сломан, хотя маршруты в порядке).

## Решения по ОС

### Windows

Скрипт сбрасывает таблицу маршрутизации, чистит DNS-кэш, перерегистрирует интерфейсы и перезапускает стек Winsock/TCP-IP. Требует прав администратора.

#### Вариант 1. Ручной запуск скрипта (Windows)

1. Запустите `windows/fix-network.ps1` от имени администратора (ПКМ → «Запуск с PowerShell» в режиме админа), либо `windows/fix-network.bat` (ПКМ → «Запуск от имени администратора»).
2. Дождитесь завершения — скрипт выведет статус каждого шага.
3. При необходимости переподключите Wi-Fi / Ethernet.

Что делает скрипт:
- `route -f` — очищает таблицу маршрутизации (кроме persistent-маршрутов).
- `ipconfig /flushdns` — чистит DNS-кэш резолвера.
- `ipconfig /registerdns` — перерегистрирует DNS-записи.
- `ipconfig /release` + `ipconfig /renew` — обновляет IP-аренду у DHCP.
- `netsh winsock reset` — сбрасывает Winsock-каталог (эффективно против «залипших» LSP от VPN-клиентов).
- `netsh int ip reset` — сбрасывает TCP/IP-стек.

> ⚠️ После `netsh winsock reset` и `netsh int ip reset` рекомендуется перезагрузка.

#### Вариант 2. Автоматизация через Планировщик задач (Windows)

Чтобы не запускать скрипт руками, можно повесить его на системное событие изменения сети.

**Через готовый XML (быстрый способ):**

```powershell
schtasks /Create /XML "windows\Fix-Network-After-VPN.xml" /TN "Fix Network After VPN"
```

**Через GUI (пошагово):**

1. Нажмите `Win + R`, введите `taskschd.msc` и нажмите Enter.
2. Справа нажмите **Создать задачу** (Create Task).
3. Вкладка **Общие**:
   - Имя задачи: `Fix Network After VPN`.
   - Поставьте галочку **Выполнять с наивысшими правами** (Run with highest privileges) — обязательно, `route` требует админа.
4. Вкладка **Триггеры → Создать**:
   - Начать задачу: **При событии** (On an event).
   - Журнал: `System`.
   - Источник: `NetworkProfile` (или `Hyper-V-NetAnv` — зависит от того, как определяется ваш tun-адаптер).
   - Альтернативный, более простой триггер: **При изменении сетевого подключения**.
5. Вкладка **Действия → Создать**:
   - Действие: **Запуск программы**.
   - Программа: `powershell.exe`.
   - Аргументы: `-WindowStyle Hidden -ExecutionPolicy Bypass -File "C:\путь\к\windows\fix-network.ps1"`.
   - Либо короткий инлайн-вариант: `-WindowStyle Hidden -Command "route /f; ipconfig /flushdns"`.
6. Вкладка **Условия**: при желании снимите «Запускать только при питании от сети».

### macOS

Скрипт `macos/fix-network.sh` сбрасывает маршруты, чистит DNS-кэш и перезапускает сетевой сервис. Требует `sudo`.

```bash
sudo bash macos/fix-network.sh
```

Что делает:
- `route -n flush` — очищает таблицу маршрутизации.
- `dscacheutil -flushcache` + `killall -HUP mDNSResponder` — сбрасывает DNS-кэш (встроенный резолвер и mDNS).
- Перезапуск сетевого сервиса (`networksetup -setnetworkserviceenabled "<service>" off/on`) — переподнимает Wi-Fi / Ethernet.
- Удаляет «осиротевшие» utun-интерфейсы (`ifconfig utunN destroy`), оставшиеся от VPN.

Если проблема повторяется, проверьте настройки DNS: **System Settings → Network → <ваш интерфейс> → Details → DNS**. Удалите вручную адреса, принадлежавшие VPN.

### Linux

Скрипт `linux/fix-network.sh` рассчитан на дистрибутивы с `systemd-resolved` и `NetworkManager` (Ubuntu, Fedora, Arch, Debian 12+). Требует `sudo`.

```bash
sudo bash linux/fix-network.sh
```

Что делает:
- `ip route flush cache` и удаление дефолтных маршрутов, указывающих на tun/wg-интерфейсы.
- `resolvectl flush-caches` — чистит кэш `systemd-resolved`.
- Удаляет остаточные VPN-интерфейсы: `ip link delete <iface>` для `tun*`, `wg*`, `tap*`, `ppp*`.
- `nmcli networking off && nmcli networking on` — перезапуск NetworkManager.
- Если NM нет — `systemctl restart systemd-networkd`.

Для дистрибутивов без NetworkManager (сервера, кастомные сборки) правьте раздел `restart_network` в скрипте под свой стек (`netplan apply`, `wicd`, `ifup/ifdown` и т.п.).
